One-line intent: a loyalty credential is a signed statement about a customer's status that the customer carries to a partner, which the partner verifies without talking to the issuer.

## The four steps

<Steps>
  <Step title="Your loyalty engine fires an event">
    A customer reaches Gold. Your existing system triggers the same milestone event it already does — a database write, a webhook, an email. Nothing in the engine changes.
  </Step>
  <Step title="AIR Kit issues a loyalty credential">
    Your backend makes one API call. A verifiable "Gold Member" credential lands in that customer's AIR Account. The customer does not need to open an app or take any action.
  </Step>
  <Step title="The customer presents the credential at a partner">
    At check-in, checkout, or app login at any partner in the ecosystem, the customer's credential is readable. No account linking. No API call back to your platform.
  </Step>
  <Step title="The partner verifies — and gets only what the program asks for">
    The partner's app calls one SDK method. A successful result includes a Verifiable Presentation. Configure the verification program to request only the fields the benefit needs, with the user's approval.
  </Step>
</Steps>
